# ADR-008 — ورود دومرحله‌ای پیامکی اختیاری برای پرسنل

تاریخ: ۲۰۲۶-۰۹-۲۴ · تصمیم: طبق درخواست مالک محصول.

## تصمیم

SMS در کنار Passkey و TOTP قابل فعال‌سازی است. رمز عبور همچنان مرحلهٔ اول
است؛ دریافت پیامک به‌تنهایی حساب یا نشست نمی‌سازد. Passkey اولویت امنیتی
خود را حفظ می‌کند. SMS در برابر فیشینگ و انتقال سیم‌کارت ضعیف‌تر است؛
داشتن Passkey یا TOTP به‌عنوان راه جایگزین توصیه می‌شود.

شمارهٔ عامل دوم از شمارهٔ مشتری یا شمارهٔ ویرایش‌پذیر پروفایل کپی نمی‌شود.
ثبت و تغییر آن به نشست کامل، رمز فعلی و تأیید کد همان شماره نیاز دارد.
PIN و کلید API اجازهٔ مدیریت عامل دوم را ندارند. ثبت عامل، نشست‌های رمزی
قدیمی را باطل و نشست راه‌اندازیِ تأییدشده را ارتقا می‌دهد.

## قرارداد

- کد شش‌رقمی تصادفی امن، عمر ۱۲۰ ثانیه، حداکثر سه تلاش.
- سهمیهٔ سه ارسال در پانزده دقیقه برای حساب، شماره و IP؛ کنترل هم‌زمان با قفل.
- کد به حساب، هدف و نشست یا بلیت مرحلهٔ دوم وابسته است؛ ارسال مجدد کد قبلی را باطل می‌کند.
- هش HMAC برای مقایسه و رمزگذاری AES-256-GCM برای تحویل موقت به Worker؛ کلید مشتق‌شده از `SMS_CREDENTIAL_KEY`.
- outbox فقط شناسهٔ چالش را نگه می‌دارد. کد خام وارد پاسخ، لاگ یا خطای ارسال نمی‌شود.
- پس از ارسال، ciphertext پاک می‌شود؛ Worker ciphertext چالش‌های منقضی را هم پاک می‌کند.
- حالت `log` و تنظیمات ناقص اجازهٔ راه‌اندازی SMS ندارند. قطعی سرویس، کنترل ورود را باز نمی‌کند.
- بلیت ورود با DELETE اتمیک مصرف می‌شود؛ رقابت دو درخواست نباید دو نشست بسازد.

## استقرار و بازگشت

مهاجرت ۰۷۶ باید پیش از نسخهٔ API و Worker اجرا شود و مجوزهای نقش برنامه
تازه شوند. API و Worker باید کلید اصلی یکسان داشته باشند. هیچ شماره یا
کلید واقعی همراه کد منتشر نمی‌شود. راهنمای تنظیم سرویس در MELIPAYAMAK.md است.

نسخهٔ قدیمی را پس از فعال‌شدن SMS برای کاربران، کورکورانه برنگردانید:
آن نسخه روش SMS را نمی‌شناسد. ابتدا دسترسی جایگزین تأییدشده برای کاربران
فراهم و با هماهنگی آنان SMS غیرفعال شود؛ جدول‌ها و سوابق مالی حذف نشوند.

## اثبات و محدودیت

`apps/api/test/sms-pin.integration.test.ts` با PostgreSQL واقعی و فرستندهٔ
جایگزینِ محلی، تأیید شماره، سهمیه، انقضا، بازپخش، رقابت و حذف عامل را می‌سنجد.
`db/test/sms-factor.sql` حفظ رفتار TOTP را بررسی می‌کند.
آزمون مرورگر مسیر تنظیم و ورود را پوشش می‌دهد. این آزمون‌ها تحویل واقعی
پیامک توسط اپراتور را تأیید نمی‌کنند؛ آزمون تحویل به شمارهٔ مجاز، مرحلهٔ عملیاتی جداست.
