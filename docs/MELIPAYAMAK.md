# اتصال ملی‌پیامک

آداپتور `melipayamak` از API کلیددار کنسول رسمی استفاده می‌کند:
`POST https://console.melipayamak.com/api/send/simple/{key}` با JSON شامل `from`، `to` و `text`.
مرجع قرارداد: https://console.melipayamak.com/send/simple (بررسی‌شده در 2026-09-23).

پذیرش ارسال فقط با HTTP موفق، JSON معتبر، `recId` مثبت و نبود خطای `status` ثبت می‌شود. این رسید، تأیید پذیرش سرویس است؛ تحویل به گوشی را ثابت نمی‌کند. بدنهٔ خطای سرویس، URL حاوی کلید و خطای خام شبکه در گزارش برنامه ذخیره نمی‌شوند. TLS معمول Node فعال است و redirect دنبال نمی‌شود.

کلید API از تنظیمات ← اعلان‌ها ← اتصال ملی‌پیامک وارد، تعویض یا صریحاً حذف می‌شود. مقدار کلید پس از ذخیره بازگردانده نمی‌شود. نام حساب/نام کاربری پنل اختیاری و صرفاً برچسب شناسایی است؛ API کلیددار از نام کاربری برای احراز هویت استفاده نمی‌کند. در تنظیمات برنامه، `notify.sms_provider` برابر `melipayamak` و `notify.sms_sender` برابر شمارهٔ فرستندهٔ تأییدشدهٔ پنل است. کلید را در جدول تنظیمات، Git یا متن گزارش نگذارید. مهاجرت 071 گزینه را اضافه می‌کند و 072 جدول جداگانهٔ اعتبارنامهٔ رمز‌شده را می‌سازد؛ سرویس فعلی یا وضعیت ارسال تغییر نمی‌کند. ذخیره با مجوز settings.security، نشست کامل و CSRF انجام می‌شود؛ شمارهٔ ویرایش جلوی بازنویسی هم‌زمان را می‌گیرد.

پیش از فعال‌سازی `notify.sms_enabled`، صف پیامک‌های معوق و گیرندگان آن‌ها بررسی شوند. ارسال آزمایشی واقعی باید به شمارهٔ مالک با اجازهٔ او انجام شود. تغییر تنظیم سرویس به‌تنهایی اثبات ارسال موفق نیست؛ کلید، اعتبار، مجوز خط و تحویل واقعی باید جدا بررسی شوند.

صف فعلی تحویل حداقل یک‌بار دارد. قطع ارتباط پس از پذیرش سرویس یا توقف Worker پیش از ثبت نتیجه می‌تواند پیام تکراری ایجاد کند؛ API مستندشده در این آداپتور کلید idempotency ندارد. خطای مبهم JSON یا پاسخ تجاری ناموفق خودکار موفق اعلام نمی‌شود. برای رسیدگی دستی به خطاهای دائمی، گزارش پنل بررسی شود.

تست قرارداد بدون ارسال پیامک:

```sh
node --experimental-strip-types --test apps/api/test/melipayamak.test.ts
```

این تست قرارداد شبکه را کنترل می‌کند؛ جای آزمون واقعی پنل و گوشی را نمی‌گیرد.

## آماده‌سازی سرور

`SMS_CREDENTIAL_KEY` یک کلید تصادفی ۳۲بایتی به صورت ۶۴ نویسه hex است و باید برای API و Worker یکسان تنظیم شود. این کلید اصلی AES-256-GCM است، نه کلید پنل ملی‌پیامک. آن را همراه فایل محیط در محل امن پشتیبان بگیرید؛ بکاپ دیتابیس به‌تنهایی راز را بازیابی نمی‌کند. تغییر یا گم‌شدن کلید اصلی باعث رد رمزگشایی می‌شود؛ کلید را بدون مهاجرت رمزها عوض نکنید. nonce تصادفی و AAD اختصاصی از جابه‌جایی یا تغییر ciphertext جلوگیری می‌کند. نام حساب در جدول جداگانه است؛ حسابرسی فقط تغییر کلید، وجود کلید و شمارهٔ ویرایش را ثبت می‌کند.

پس از تغییر کلید API در صفحه، Worker برای پیام بعدی آن را از مخزن رمز‌شده می‌خواند؛ restart لازم نیست. سرویس‌های قبلی همچنان از SMS_API_KEY محیط استفاده می‌کنند. خطای پیکربندی پیامک فقط هنگام استفاده از کانال پیامک رخ می‌دهد و صف Push موجودی را نمی‌میراند.
