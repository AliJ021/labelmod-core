# اتصال ملی‌پیامک

در حالت «کلید کنسول»، ارسال متن آزاد از API رسمی استفاده می‌کند:
`POST https://console.melipayamak.com/api/send/simple/{key}` با JSON شامل `from`، `to` و `text`.
مرجع قرارداد: https://console.melipayamak.com/send/simple (بررسی‌شده در 2026-09-23).

پذیرش ارسال فقط با HTTP موفق، JSON معتبر، `recId` مثبت و نبود خطای `status` ثبت می‌شود. این رسید، تأیید پذیرش سرویس است؛ تحویل به گوشی را ثابت نمی‌کند. بدنهٔ خطای سرویس، URL حاوی کلید و خطای خام شبکه در گزارش برنامه ذخیره نمی‌شوند. TLS معمول Node فعال است و redirect دنبال نمی‌شود.

کلید API از تنظیمات ← اعلان‌ها ← اتصال ملی‌پیامک وارد، تعویض یا صریحاً حذف می‌شود. مقدار کلید پس از ذخیره بازگردانده نمی‌شود. در حالت کنسول نام حساب اختیاری است. در حالت پنل، نام کاربری همراه کلید پنل برای احراز هویت لازم است. ارسال متن آزاد خط فرستنده می‌خواهد و ارسال خدماتی از کد پترن همان کاربرد استفاده می‌کند. کلید را در جدول تنظیمات، Git یا متن گزارش نگذارید. مهاجرت 071 گزینه را اضافه می‌کند و 072 جدول جداگانهٔ اعتبارنامهٔ رمز‌شده را می‌سازد؛ سرویس فعلی یا وضعیت ارسال تغییر نمی‌کند. ذخیره با مجوز settings.security، نشست کامل و CSRF انجام می‌شود؛ شمارهٔ ویرایش جلوی بازنویسی هم‌زمان را می‌گیرد.

پیش از فعال‌سازی `notify.sms_enabled`، صف پیامک‌های معوق و گیرندگان آن‌ها بررسی شوند. ارسال آزمایشی واقعی باید به شمارهٔ مالک با اجازهٔ او انجام شود. تغییر تنظیم سرویس به‌تنهایی اثبات ارسال موفق نیست؛ کلید، اعتبار، مجوز خط و تحویل واقعی باید جدا بررسی شوند.

برای رسید فاکتور، وضعیت پذیرش و شناسهٔ سرویس ذخیره می‌شوند. اگر نتیجهٔ ارسال مبهم باشد، پیش از هر ارسال مجدد وضعیت آن را در پنل سرویس بررسی کنید.

تست قرارداد بدون ارسال پیامک:

```sh
node --experimental-strip-types --test apps/api/test/melipayamak.test.ts
```

این تست قرارداد شبکه را کنترل می‌کند؛ جای آزمون واقعی پنل و گوشی را نمی‌گیرد.

## آماده‌سازی سرور

`SMS_CREDENTIAL_KEY` یک کلید تصادفی ۳۲بایتی به صورت ۶۴ نویسه hex است و باید برای API و Worker یکسان تنظیم شود. این کلید اصلی AES-256-GCM است، نه کلید پنل ملی‌پیامک. آن را همراه فایل محیط در محل امن پشتیبان بگیرید؛ بکاپ دیتابیس به‌تنهایی راز را بازیابی نمی‌کند. تغییر یا گم‌شدن کلید اصلی باعث رد رمزگشایی می‌شود؛ کلید را بدون مهاجرت رمزها عوض نکنید. nonce تصادفی و AAD اختصاصی از جابه‌جایی یا تغییر ciphertext جلوگیری می‌کند. نام حساب در جدول جداگانه است؛ حسابرسی فقط تغییر کلید، وجود کلید و شمارهٔ ویرایش را ثبت می‌کند.

پس از تغییر کلید API در صفحه، Worker برای پیام بعدی آن را از مخزن رمز‌شده می‌خواند؛ restart لازم نیست. سرویس‌های قبلی همچنان از SMS_API_KEY محیط استفاده می‌کنند. خطای پیکربندی پیامک فقط هنگام استفاده از کانال پیامک رخ می‌دهد و صف Push موجودی را نمی‌میراند.

## راه‌اندازی از داخل پنل

- کلید وب‌سرویس پنل همراه با نام کاربری همان پنل در حالت «کلید وب‌سرویس پنل + نام کاربری» استفاده می‌شود. برای کلید کنسول، حالت «کلید کنسول» را انتخاب کنید. دکمهٔ استعلام اعتبار فقط مشخصات ذخیره‌شده را بررسی می‌کند.
- در ملی‌پیامک، یک پترن خدماتی تأییدشده برای ورود با تنها متغیر کد، و در صورت نیاز یک پترن جدا برای رسید با سه متغیر شمارهٔ فاکتور، مبلغ به تومان و لینک ثبت کنید. شناسه و رونوشت متن را در اعلان‌ها وارد کنید. متن واقعی پترن از ملی‌پیامک می‌آید. عدم تعیین پترن یعنی استفاده از خط تأییدشده و متن آزاد.
- ارسال واقعی و سرویس‌دهنده را در اعلان‌ها انتخاب کنید. برای رسید، ارسال فاکتور، نشانی عمومی و رضایت مشتری هم بررسی می‌شوند. در صندوق، رضایت دریافت رسید و رضایت تبلیغات دو انتخاب جداگانه‌اند. در مشتریان، فیلتر رضایت برای هر گروه وجود دارد.
- در صفحهٔ هر فاکتور، پذیرش رسید جدید در ملی‌پیامک و مرجع پیگیری آن قابل مشاهده است. قطع ارتباط پس از ارسال با وضعیت نامعلوم برای تطبیق باقی می‌ماند. تحویل گوشی از پذیرش سرویس قابل استنتاج نیست.
- منابع سرویس‌دهنده: [کنسول خدماتی](https://console.melipayamak.com/send/shared)، [استعلام اعتبار کنسول](https://console.melipayamak.com/receive/credit)، [کتابخانهٔ رسمی REST پنل](https://github.com/Melipayamak/melipayamak-Asp.net-Core/blob/master/RestClientAsync.cs).
