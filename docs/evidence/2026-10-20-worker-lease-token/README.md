# شواهد توکن اجارهٔ Outbox — مهاجرت ۱۰۰

همهٔ اجراها روی PostgreSQL 16.13 محلی و دیتابیس یک‌بارمصرف انجام شدند. هر probe داخل تراکنش است و با `ROLLBACK` تمام می‌شود. هیچ سرور TEST، سایت یا دادهٔ واقعی لمس نشد.

## پیش و پس

| پرونده | مبنا | نتیجه |
|---|---|---|
| `core-worker-lease-baseline-probe.sql` / `.log` | main `4cdde906` (تا ۰۹۹)، فقط مهاجرت | A کهنه پیامِ B را `sent` کرد؛ جدا از آن، `fail` پیامِ B را `pending` کرد. هر دو با `claimed_by = B`. همان یافتهٔ ریشه بازتولید شد. |
| `core-worker-lease-after-probe.sql` / `.log` | همان main به‌علاوهٔ ۱۰۰ | `complete(id, token_a)` = `f` و `fail(id, token_a, …)` = `lost`. سطر `sending` می‌ماند و مال B است، بی `sent_at` و بی `last_error`. نسخهٔ بی‌توکن وجود ندارد. کنترل مثبت: B می‌بندد و توکن پاک می‌شود. |

تنها تفاوت سناریو: اجارهٔ ۰ ثانیه دیگر پذیرفته نیست (بازهٔ ۳۰ تا ۳۶۰۰). پس انقضای A با جلوبردن `next_attempt_at` شبیه‌سازی شد؛ این همان چیزی است که گذر زمان می‌سازد.

## مرز

- **آمادهٔ ادغام ≠ آمادهٔ تولید.** نصب، استقرار و Worker دوم انجام نشده‌اند.
- `docker-compose.prod.yml` فقط خط `all` را دارد. جفت `web`/`notify` تصمیم استقرار است.
- تأخیر واقعی صف در این PR اندازه‌گیری نشده است. SLO پیشنهادی (۹۵٪ زیر ۳ ثانیه، ۹۹٪ زیر ۱۰ ثانیه) همچنان اثبات‌نشده است.
- تحویل همچنان «حداقل یک بار» است. توکن جلوی تغییر وضعیت توسط مالک کهنه را می‌گیرد، نه ارسالی را که پیش از ازدست‌رفتن اجاره شروع شده بود.
