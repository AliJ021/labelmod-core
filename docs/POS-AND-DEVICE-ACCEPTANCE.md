# صندوق، PIN و چاپ بارکد

## مسیرهای رابط کاربری

| کار | مسیر |
| --- | --- |
| افزودن با نام | صندوق ← جست‌وجوی نام محصول ← انتخاب محصول ← رنگ ← سایز |
| پرداخت ترکیبی | صندوق ← روش اول و مبلغ بخشی ← دریافت وجه ← روش بعدی و مانده ← نهایی‌کردن |
| موجودی هر تنوع | کالا و قیمت ← باز کردن محصول ← موجودی محصول |
| چاپ لیبل | همان محصول ← انتخاب تنوع‌های جدول ← چاپ لیبل بارکد ← پیش‌نمایش ← چاپ |
| اندازهٔ رول لیبل | یک انتخاب برای صفحهٔ کالا و فهرست چاپ گروهی، ماندگار روی همان دستگاه؛ پیش‌فرض ۵۰×۳۰ |
| ساخت/تغییر/حذف PIN شخصی | تنظیمات ← کاربران و امنیت ← PIN من — ساخت و تغییر |
| فعال‌سازی پیامک ورود | تنظیمات ← کاربران و امنیت ← ورود دومرحله‌ای ← کد ورود با پیامک |

جست‌وجوی صندوق محصول مادر را نشان می‌دهد، سپس رنگ و سایز انتخاب می‌شوند.
بارکدخوان و دوربین قبلی همچنان قابل استفاده‌اند. موجودی قابل فروش صندوق
به انبار انتخاب‌شده وابسته است؛ موجودی صفحهٔ کالا مجموع انبارهای شعبه‌های مجاز است.
قیمت و کنترل موجودی همچنان سمت سرور اعمال می‌شوند. قیمت خرید به صندوق‌دار نمایش داده نمی‌شود.

پرداخت ترکیبی می‌تواند بیش از دو بخش داشته باشد. برای کارت‌خوان، شمارهٔ
پیگیری رسید وارد شود؛ انتخاب روش کارت‌خوان به معنی ارسال فرمان بانکی به
دستگاه نیست. مبلغ رابط تومان و مبلغ API ریال است. فهرست دریافتی از سرور
می‌آید و بارگذاری مجدد نباید باعث دوباره‌گرفتن وجه شود.

PIN فقط برای بازکردن قفل نشست روز جاری روی دستگاه تأییدشده است؛ جای رمز
کامل یا عامل دوم نیست. ساخت و تغییر آن رمز فعلی می‌خواهد.

## پذیرش TEST پس از بازسازی — سناریوهای مالک

این جدول آمادهٔ اجراست؛ هیچ ردیف آن به معنی اجرای موفق روی سرور بازسازی‌شده نیست. پیش از شروع، SHA مستقر، نسخهٔ افزونه، شعبه/انبار آزمایشی و شناسهٔ جدید سفارش را در گزارش خصوصی ثبت کنید. سفارش‌ها و نگاشت‌های پیش از بازسازی، شاهد سلامت اتصال تازه نیستند.

| سناریو | نتیجهٔ مورد انتظار | شاهد لازم |
|---|---|---|
| شمارهٔ اجباری روشن/خاموش | سیاست تازه در صندوق اعمال شود؛ شمارهٔ تازه نام مشتری بخواهد | وضعیت تنظیم، نتیجهٔ بدون شماره و با مشتری ساختگی |
| قیمت دستی تومان | کنترل قیمت واحد کار کند؛ جمع ردیف و مبلغ سرور دقیق بماند | مقدار قبل/بعد و فاکتور آزمایشی |
| پیش‌فاکتور | قبل از نهایی‌سازی اقلام/مبالغ چاپ شوند؛ فروش، وصول یا حرکت انبار نسازد | شناسهٔ پیش‌نویس و مقایسهٔ سوابق پیش/پس |
| تنوع ووکامرس با SKU موجود | قیمت و موجودی همان تنوع به‌روز شود؛ نام متفاوت محصول اتصال را عوض نکند | SKU، شناسهٔ تنوع و مقادیر دو طرف |
| سفارش پرداخت‌شده با کوپن جزئی و ۱۰۰٪ | سفارش به حسابداری برسد؛ موجودی با مقدار فروش تغییر کند، حتی اگر مبلغ نهایی صفر باشد | شناسهٔ سفارش/فاکتور، تخفیف و حرکت انبار |
| پرداخت در محل هنگام سفارش | موجودی فیزیکی ثابت؛ رزرو بیشتر و موجودی قابل فروش کمتر شود | هر سه مقدار پیش/پس، همان SKU و انبار |
| تحویل و وصول COD، سپس ارسال تکراری | خروج قطعی و دریافت یک‌بار ثبت شود؛ تکرار اثر تازه نداشته باشد | شاهد تحویل/وصول، سند و شمار حرکت‌ها |
| لغو COD پیش از تحویل | رزرو آزاد شود؛ خروج یا دریافت وجه ساختگی ثبت نشود | سفارش، رزرو و سوابق مالی |
| مرجوعی COD پیش از اجرای صف | فروش اصلی و مرجوعی با شاهد مستقل تحویل/وصول تطبیق داده شوند؛ دوباره‌کاری نکنند | ترتیب رویدادها و ارتباط اسناد |
| تعویض گران‌تر/ارزان‌تر و فاکتور نسیه | دریافت/بازپرداخت اختلاف و سیاست انتخاب‌شدهٔ بدهی درست اعمال شود | تنظیم سیاست، فاکتور اولیه و اسناد مرتبط |
| تسویهٔ گروهی برداشت پرسنل | فقط موارد انتخاب‌شده با تاریخ/مدیر و سابقه تسویه شوند؛ خزانه و دفتر تغییر نکند | فیلتر/انتخاب، سابقه و مقایسهٔ دفتر |
| چاپ رسید و لیبل | رسید ۸۰mm و لیبل ۵۰×۳۰؛ ارقام لاتین؛ بارکد تنوع درست اسکن شود | کاغذ واقعی، SKU حاصل اسکن و ابعاد |

زیبال، پیامک و پرداخت بانکی واقعی در این برنامه فعال نمی‌شوند. اسنپ‌پی/دیجی‌پی فعلاً فقط روش ثبت دستی هستند. یک پاسخ HTTP موفق به‌تنهایی شاهد ثبت فاکتور یا کسر موجودی نیست؛ شناسهٔ معتبر و اثر قابل ردیابی باید با هم دیده شوند.

## آزمون فیزیکی در رایانه صندوق

این بخش پس از استقرار نسخهٔ تست‌شده، با حضور کاربر اجرا و نتیجه ثبت شود:

1. با یک محصول آزمایشی چندرنگ و چندسایز، افزودن از نام و بارکد را مقایسه کنید؛ SKU و تعداد باید یکسان باشند.
2. لیبل یک تنوع را با اندازهٔ واقعی رول بسازید. مقیاس چاپ ۱۰۰٪، سربرگ/پابرگ خاموش و اندازهٔ کاغذ مطابق لیبل باشد. تنوع بی‌قیمت یا بی‌بارکد پیش از چاپ هشدار می‌گیرد و لیبلش «بدون قیمت» یا فقط SKU دارد؛ هشدار مانع چاپ نیست.
3. یک برچسب چاپ کنید؛ نام، رنگ، سایز، قیمت تومان و بارکد کامل و بدون بریدگی باشند. سپس با بارکدخوان آن را اسکن کنید.
4. از دوربین موبایل همان بارکد را بخوانید. اختلاف فوکوس/نور و کیفیت چاپ فقط در این مرحله معلوم می‌شود.
5. یک فاکتور آزمایشی با نقد + کارت‌خوان + نقد ثبت کنید؛ مجموع دریافتی، مانده، رسید و گزارش شیفت را تطبیق دهید.
6. رسید روی MEVA TP-UNW رایانهٔ صندوق چاپ شود؛ فارسی، عرض کاغذ، برش و چند نسخه کنترل شوند.
7. هر فرمان بانکی واقعی و تحویل پیامک با شماره و مبلغ مجاز، جداگانه و با اجازهٔ مالک تست شود.

عبور آزمون خودکار، تأیید درایور چاپگر، اندازهٔ رول، کابل بارکدخوان یا اتصال PSP نیست.
هیچ شماره، رمز، کلید API یا سند مالی واقعی در گزارش عمومی آزمون قرار نگیرد.
