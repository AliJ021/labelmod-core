# قواعد لایه API

جزئیات کامل در `docs/SECURITY.md` — الزام‌آور است.

## ورودی و خروجی
- **Zod در هر مرز API.** هیچ ورودی بدون Schema وارد منطق نمی‌شود.
- پول در JSON **رشته** است، نه عدد. `number` جاوااسکریپت مبالغ ریالی
  بزرگ را خراب می‌کند.
- خطا به کاربر بدون Stack Trace؛ جزئیات فقط در لاگ با Correlation ID.

## قیمت
- **قیمت از `catalog.price` می‌آید، نه از کلاینت** — مگر با
  `sale.price_override` (مهاجرت ۰۱۰، خواستهٔ مالک: «مثل دشت»).
- قیمت دستی در `unit_price` می‌نشیند و قیمت فهرست در `list_price`:
  **فاکتور یک عدد نشان می‌دهد**، نه قیمت و تخفیف کنار هم.
- **سقف از «کاهش کل» سنجیده می‌شود، نه از تخفیف.** تخفیف به‌علاوه
  تفاوت قیمت دستی، در یک عدد، از همان نردبان `sale.discount` /
  `sale.discount_high` می‌گذرد. بدون این، قیمت دستی راهِ دور زدن سقف
  تخفیف بود.
- `discount.require_reason_above_percent` را یک Trigger روی
  `invoice_line` اجبار می‌کند، نه لایه API — تا هیچ مسیر تازه‌ای
  نتواند فراموشش کند.

## احراز هویت
- نشست: توکن مات ۳۲ بایتی، **SHA-256 آن** در DB. **JWT ممنوع** — ابطال
  فوری همه نشست‌ها الزام سند است.
- کوکی: `HttpOnly` · `Secure` · `SameSite=Strict`.
- رمز: Argon2id `m=65536, t=3, p=4`. bcrypt و PBKDF2 برای رمز جدید ممنوع.
- PIN صندوق‌دار فقط قفل‌گشای نشست موجود است. **هرگز** بازپرداخت، ابطال
  فاکتور، تغییر قیمت یا اصلاح موجودی را مجاز نمی‌کند.

## Idempotency
هر Endpoint تغییردهنده وضعیت:
1. هدر `Idempotency-Key` با Cache پاسخ ۲۴ ساعته
2. درج در `platform.inbox_message` با یکتایی `(source, event_id)`
3. اثر و درج Inbox در **یک تراکنش**
4. پیامک/PDF/ووکامرس در `outbox_message` — **بعد از** Commit

## محدودیت نرخ
ورود (۵/دقیقه بر IP) · ارسال OTP (۳ در ۱۵ دقیقه بر شماره و بر IP) ·
Endpointهای پرداخت.

## مجوز
از `identity.permission_rule` بخوان. **هیچ شرط دسترسی hardcode نکن.**
عملیات نیازمند تأیید باید `approval_request` با دلیل متنی اجباری بسازد.
