# Label Mod Core

پلتفرم یکپارچه لیبل مد — حسابداری، انبار، خرید، فروش و صندوق فروشگاهی.

> **وضعیت: هسته مالی ساخته و تست شده. آماده بهره‌برداری نیست.**
> پیش از ورود هر داده واقعی، بخش «تصمیم‌های باز» پایین را بخوانید.

---

## چه چیزی تا الان ساخته شده

هسته مالی و انباری — یعنی همان بخشی که اگر اشتباه باشد، بقیه سیستم بی‌معنا
می‌شود. کاملاً نوشته، اجرا و تست شده است:

| بخش | وضعیت |
| --- | --- |
| اسکیمای کامل پایگاه داده (۸ اسکیما، ۳۵ جدول) | ✅ |
| انبار حرکت‌محور + میانگین موزون متحرک | ✅ تست‌شده |
| رسید خرید با تخصیص هزینه حمل (Landed Cost) | ✅ تست‌شده |
| فروش با Snapshot قیمت و بهای تمام‌شده | ✅ تست‌شده |
| مرجوعی با بهای Snapshot فروش اصلی | ✅ تست‌شده |
| بستن شیفت و سند تجمیعی | ✅ تست‌شده |
| دفتر کل دوبل با توازن اجباری در سطح دیتابیس | ✅ تست‌شده |
| موتور ثبت داده‌محور (کدینگ قابل تغییر بدون کد) | ✅ تست‌شده |
| Idempotency و کنترل همزمانی | ✅ تست‌شده |
| لاگ حسابرسی با زنجیره هش | ✅ تست‌شده |
| Outbox برای پیامک/PDF/ووکامرس | ✅ ساختار آماده |

**هنوز ساخته نشده:** رابط کاربری، API، صندوق، افزونه ووکامرس، گزارش‌ها،
چاپ رسید، مهاجرت داده.

## راه‌اندازی

```bash
cp .env.example .env      # رمز پایگاه داده را عوض کنید
docker compose up -d db

export DATABASE_URL='postgres://labelmod:رمز@localhost:5432/labelmod'
ops/db.sh migrate         # ساخت اسکیما
ops/db.sh seed            # کدینگ حساب، قواعد ثبت، تنظیمات
ops/db.sh test            # اجرای تست‌ها — باید همه پاس شوند
```

اگر `ops/db.sh test` سبز نشد، هیچ کار دیگری نکنید تا علتش پیدا شود.

## اصولی که در کد اجبار شده‌اند

این‌ها توصیه نیستند — دیتابیس آن‌ها را رد می‌کند:

- **هر سند حسابداری باید متوازن باشد.** سند نامتوازن با `CONSTRAINT TRIGGER`
  معوق رد می‌شود، نه با بررسی در کد.
- **حرکت انبار تغییرناپذیر است.** `UPDATE` و `DELETE` روی `stock_movement`
  خطا می‌دهند. اصلاح فقط با حرکت معکوس.
- **سند نهایی حذف نمی‌شود.** اصلاح فقط با سند معکوس.
- **لاگ حسابرسی فقط درج‌شدنی است**، با زنجیره هش برای تشخیص دستکاری.
- **موجودی منفی نمی‌شود** مگر با مجوز صریح.
- **پول هرگز float نیست.** `NUMERIC(18,0)` ریالی در SQL، `bigint` در
  TypeScript، رشته در JSON.
- **فروش هم‌زمان اثر تکراری نمی‌سازد.** قفل بدبینانه روی سطر موجودی.
- **شماره فاکتور فقط در لحظه Commit تخصیص می‌یابد**، بدون پرش.

## دو الگویی که ارزش دانستن دارند

**۱. بهای تمام‌شده بدون رانش گرد کردن.** به‌جای نگهداری `avg_cost`،
مقدار `total_value` نگه داشته می‌شود و میانگین لحظه‌ای محاسبه می‌شود.
هنگام تخلیه کامل موجودی، آخرین واحدها کل ارزش باقی‌مانده را جذب می‌کنند و
مبلغ سند COGS همان کاهش واقعی ارزش انبار است. نتیجه: **دفتر کل و انبار
هیچ‌وقت — حتی یک ریال — از هم جدا نمی‌افتند.** تست `edge_cases.sql`
دقیقاً همین را می‌سنجد.

**۲. تصمیم‌های باز، داده‌اند نه کد.** کدینگ حساب در `ledger.account`،
نگاشت رویداد به سند در `ledger.posting_rule`، سقف دسترسی در
`identity.permission_rule`، و پانزده تصمیم بازِ سند در `platform.setting`.
وقتی حسابدار نظرش عوض شود، یک `UPDATE` کافی است — نه یک Deploy.

## ⚠️ تصمیم‌های باز — پیش از ورود داده واقعی

مقادیر فعلی **پیش‌فرض پیشنهادی‌اند** و باید تصویب شوند:

| تصمیم | مقدار فعلی | تصویب با |
| --- | --- | --- |
| کدینگ حساب (`db/seed/010_accounts.sql`) | پیشنهادی | حسابدار |
| روش بهای تمام‌شده | میانگین موزون متحرک | حسابدار |
| واحد پول | ریال (نمایش تومان) | حسابدار |
| تجمیع سند فروش | در سطح شیفت | حسابدار |
| نرخ ارزش افزوده | ۱۰٪ — و فعلاً **خاموش** | مشاور مالیاتی |
| صورتحساب الکترونیکی | `none` | مشاور مالیاتی |
| سال مالی ۱۴۰۵ | ۱ فروردین تا ۲۹ اسفند | حسابدار |
| سقف تخفیف نقش‌ها | ۱۰٪ صندوق‌دار، ۲۵٪ سرپرست | مالک کسب‌وکار |
| مهلت مرجوعی | ۷ روز | مالک کسب‌وکار |
| دوره تسویه و کارمزد کارت‌خوان | ۱ روز، ۰٪ | PSP |

فهرست کامل: `SELECT key, value, description FROM platform.setting WHERE requires_approval;`

## ساختار

```
db/migrations/   اسکیما و توابع — شماره‌دار، SQL خام، قابل حسابرسی
db/seed/         کدینگ حساب، قواعد ثبت، تنظیمات، داده مرجع
db/test/         تست‌های مالی — در CI اجرا می‌شوند
docs/            تصمیمات معماری (ADR)
ops/             اسکریپت‌های مهاجرت، تست و بکاپ
apps/            (بعدی) API، صندوق، پنل مدیریت
```

## قدم بعدی

۱. تصمیم‌های جدول بالا را با حسابدار قفل کنید.
۲. لایه API و صندوق ساخته شود.
۳. مهاجرت داده واقعی + شمارش فیزیکی نمونه‌ای.
۴. اجرای موازی با سیستم فعلی تا سه روز بدون مغایرت.
